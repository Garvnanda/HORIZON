## 1 · Transport

**Demo (what ships):** static JSON files. No server. The frontend fetches `./mock/<file>.json`. Fully offline — PS hard requirement, no cloud calls at inference, ever.

**Later (optional, not for the SIH demo):** a local FastAPI maps each endpoint 1:1 to the same JSON shapes. Nothing about the frontend changes.

**Computed client-side, never fetched:** alert fired/not, `fired_at_step`, `lead_time_windows`, tier, and the alert marker position. All are a pure function of (`p_frac`, `threshold`, `ground_truth.first_attack_window`). The threshold slider is live (frontend.md) — a round trip per drag is not acceptable.

```
computeAlert(p_frac, threshold, firstAttackWindow):
  firedAtStep = first k where p_frac[k] >= threshold, else null
  fired       = firedAtStep != null
  leadTime    = fired && firstAttackWindow != null ? firstAttackWindow - firedAtStep : null
  peak        = max(p_frac)
  tier        = peak < 0.40 ? "monitor"
              : peak < 0.66 ? "suspicious"
              : peak < 0.90 ? "elevated"
              :               "critical"
```

| Method | Path | Demo file | Purpose |

## 3 · Schemas

### 3.1 `GET /api/hosts`

```json
{
  "schema_version": "v4.0",
  "hosts": [
    {
      "host": "192.168.10.15",
      "capture": "ids2017-thursday",
      "scenario": "infiltration",
      "true_class": "Infiltration",
      "n_windows": 180,
      "available_t": [40, 52],
      "peak_p_frac": 0.86,
      "has_counterfactual": true
    }
  ]
}
```

`available_t` — the window indices for which a precomputed forecast exists (demo). In a live system, any `t >= 20` is valid.

```json
    "current_stage": "Initial Access",

    "isolate_host": {
      "applied_at_step": 1,

      "clamped_features": ["n_distinct_dst_ip", "n_distinct_dst_port", "bytes_out", "external_ratio"]

  "ground_truth": {
    "attack_class": "Infiltration",
    "first_attack_window": 11
  }

```

**Rules.**
- `history` — exactly 20 entries, `window_idx` = `t-19 .. t`.
- `samples` — exactly `n_samples` rows, each length `horizon`.
- All `features` / `trajectory_mean` values in **original units** (frontend converts nothing).
- `ground_truth` and `trajectory_mean[].actual` — present only when `demo_mode: true`.
- `alert.reference` is a convenience snapshot at `default_threshold`. The frontend recomputes from the live slider and ignores it except as a sanity check.
- `counterfactuals` keys are fixed: `do_nothing`, `isolate_host`, `rate_limit`. `has_counterfactual: false` hosts still include `do_nothing`.

### 3.7 `GET /api/network?capture=`

Internal host-communication graph for the macro scene. `states.parquet` does not
keep peer identity, so this comes from `network_<capture>.json` (notebook) or the
mock bundle; live mode without that file returns nodes only.

```json
{
  "schema_version": "v4.0",
  "capture": "ids2017-thursday",
  "nodes": [
    { "host": "192.168.10.15", "subnet": "192.168.10", "n_flows": 1300,
      "n_windows": 180, "kind": "workstation", "is_demo": true, "is_target": false }
  ],
  "edges": [
    { "src": "192.168.10.15", "dst": "192.168.10.5", "flows": 62, "internal": true,
      "attack": true, "stage": 2 }
  ],
  "note": "present only on the nodes-only fallback"
}
```

- `kind` — `gateway` / `domain-controller` / `server` / `workstation` / `external`.
- `is_target` — high-value node (the crown jewel), for the scene.
- `edge.attack` / `edge.stage` — present on kill-chain edges; `stage` orders the spread (1 = earliest). Absent on normal edges.
- `ext:internet` is a single aggregated external pseudo-node.

## 4 · Feature keys (fixed order everywhere)

```
n_flows  n_distinct_dst_ip  n_distinct_dst_port  new_peer_rate  fail_ratio
bytes_out  bytes_in  io_ratio  mean_duration  external_ratio
```

The model input vector is these 10 **+ `intervention`** (control channel, 0 except in counterfactual rollout) = 11 dims. The model predicts 10. `intervention` never appears in this contract — it is internal to the rollout.
